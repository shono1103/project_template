# add-task

`job/<案件名>/task/` にタスクを1件作る。実体を `task/list/<タスク名>.md` に置き、
初期状態のディレクトリに `../list/<タスク名>.md` を指す相対シンボリックリンクを張る。

**このスキルの肝は、会話の文脈をそのまま材料にすること。** タスクは多くの場合
「今この会話で分かったこと」から生まれる。ゼロから聞き出すと、直前に話していた内容を
人にもう一度言わせることになる。**まず文脈から埋め、足りないものだけ聞く。**

**task は必ず調査を伴う。調査を始めるときに作る** (詳細は [CLAUDE.md](../../../CLAUDE.md) の
「作業の進め方」)。調べた過程は task ではなく daily に書くので、このスキルは
**結論の器を作るだけ**で、中身を書き切ろうとしない。

## 引数

* **タスクの内容** — 何をするか。省略時は直前の会話から拾う。
* **案件名** — 省略時は既存の案件から決める (1件だけならそれ、複数なら聞く)。
* **初期状態** — `todo` / `pending` / `progress` のいずれか。省略時は聞く。

## 手順

### 1. 先例を探す

```sh
# 案件が2件以上あるときだけ意味がある
find job -mindepth 1 -maxdepth 1 -type d -not -name template | sort
```

**案件が2件以上あるなら `/find-precedent` を先に回す。** 同じ罠を過去に踏んでいれば、
タスクの `## 内容` と `## 完了条件` の精度がその時点で上がる。
1件目の案件なら探す先が無いので飛ばす。

### 2. 文脈から材料を集める

会話から次を拾い、**埋まったものは聞かない。**

| 項目 | 拾い方 |
| --- | --- |
| タイトル | 話していたことを一文にする |
| 内容 | 「何を明らかにしたいか」。背景と、なぜ今やるのか |
| 完了条件 | 「何が分かれば / 何ができれば終わりか」 |
| 参照先 | この会話で読んだファイル・調査記録・QA のパス |
| タスク名 | タイトルから英小文字とハイフンで作る (`oauth-scope-decision`) |

**タスク名は内容が分かる長さにする。** `fix` `check` のような語だけだと
`ls task/todo/` で何のタスクか分からず、実体を開かないと判断できなくなる。

### 3. 案件を決める

```sh
find job -mindepth 1 -maxdepth 1 -type d -not -name template | sort
```

* 1件だけならそれを使う。複数あって会話から特定できなければ聞く
* **どれにも当てはまらない場合は案件を作る。**

```sh
cp -R job/template job/<案件名>
```

**案件を作ったら `job/<案件名>/MEMORY.md` の `## 属性` を必ず埋める。**
これが `/find-precedent` の検索キーなので、空だと後から先例として引けない
(埋めるのは属性だけでよい。前提と決定は作業しながら溜まる)。

### 4. 足りないものだけ聞く

手順2で埋まらなかったものを **AskUserQuestion で1回にまとめて聞く。**
既に分かっていることを聞き返さない。

聞く候補:

| 聞くこと | 選択肢の作り方 |
| --- | --- |
| どの案件か | 既存の案件 + 「新しく作る」 |
| 初期状態 | `progress` (今から着手) / `todo` (後でやる) / `pending` (待ちがある) |
| タスクの粒度 | 1件にまとめる / 複数に割る (割るなら分け方の案を出す) |
| 対応する手順書 | 既存の `test/<領域>/<機能>/` + 「無い」 |
| 仕上げ処理 | コミットまでやる / ファイルを作るだけ |

* **`pending` を選ぶなら待っている相手を必ず聞く。** `blockedBy` が空の `pending` は
  待ちが解けたか判定できず、置いたまま忘れられる
* **粒度は迷ったら聞く。** 後から割るのは実体・リンク・参照先の3箇所を直す作業になり、
  最初に割るより高くつく

### 5. 実体を作る

```sh
J="job/<案件名>/task"
cp "$J/list/template.md" "$J/list/<タスク名>.md"
```

frontmatter は2項目だけ。**状態は書かない** (リンクの位置が正)。

```yaml
---
blockedBy:                    # pending のときだけ埋める。それ以外は []
  - qa/oauth-scope            # qa/<名前> / task/<タスク名> / other: <待っているもの>
test:                         # 対応する手順書。無ければ []
  - test/api/oauth/
---
```

本文は `## タイトル` `## 内容` `## 完了条件` を埋め、`## 参照先` に会話で読んだパスを
日付つきで並べる。**`## 結果` は空のまま残す** (完結していないものを埋めると、
後から読んだときに結論が出ているのか判断できない)。

**手順書 (`.feature`) はこのスキルでは作らない。** どの機能ディレクトリに置くかは
人が決めた方がよく、`test:` に書いたパスが無ければ `/verify-task` 側が指摘する。

### 6. リンクを張る

```sh
cd "$J/<初期状態>" && ln -s "../list/<タスク名>.md" "<タスク名>.md" && cd -
```

**相対パスで張る。** 絶対パスにすると、リポジトリを別の場所に clone した時点で全部壊れる。

### 7. 整合性を確認する

```sh
J="job/<案件名>/task"
L="$J/<初期状態>/<タスク名>.md"

test -L "$L" && echo "リンク: OK"
readlink "$L"                       # ../list/<タスク名>.md であること
test -e "$L" && echo "リンク先: OK" # 壊れていないこと
```

`pending` にしたなら、待ち先が実際に読めることも確認する。

```sh
awk 'NR==1 && $0=="---"{f=1;next} f && $0=="---"{exit}
     f && /^blockedBy:/{b=1;next}
     f && b && /^  *- /{sub(/^  *- /,"");print;next}
     f && b{exit}' "$J/list/<タスク名>.md"
```

出力が空なら `pending` にしてはいけない。`todo` に張り直すか、待ち先を書く。

### 8. 記録を残して仕上げる

作業記録は自分のセッションディレクトリに残す。**task には過程を書かない**ので、
「なぜこのタスクを切ったか」はここに書く。

```sh
S="$(./daily/create_session.sh)"
cp daily/template/_.md "$S/<名前>.md"
```

仕上げ処理を「コミットまで」と選ばれた場合はコミットする。

```sh
git add job/<案件名> daily && git commit
```

**push はしない** (要求されたときだけ行う)。
最後に `/reload-project` を勧める (MEMORY.md はタスクを増やすと古くなる)。

## 中断する条件

以下に当たったら作らずに止め、状況を報告する。

* 同名のタスクが `list/` に既にある (**上書きしない**)
* 初期状態のディレクトリに同名のリンクが既にある
* `pending` なのに待っている相手が分からない
* タスクの内容が会話からも引数からも定まらない
  (**推測で作らない。** 中身の無いタスクは `todo/` に溜まって判断を鈍らせる)

## 出力フォーマット

```
作成しました: acme-site / oauth-scope-decision

  実体: job/acme-site/task/list/oauth-scope-decision.md
  状態: pending (← qa/oauth-scope)
  手順書: test/api/oauth/

  タイトル: OAuth スコープの確定
  完了条件: 必要なスコープが確定し、申請先が決まっている

acme-site の現在の状態:
  progress: 1 / pending: 1 / todo: 2 / done: 3

記録: daily/2026-09/02/agents/claude-code/<セッションID>/oauth-scope.md
MEMORY.md が古くなりました。`/reload-project` での更新を推奨します。
```

複数まとめて作った場合は1件ずつ並べ、最後に状態を集計する。
