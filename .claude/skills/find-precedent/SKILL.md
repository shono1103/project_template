# find-precedent

**過去の案件の蓄積を、今の作業に効く形で引き出す。** 参照のみ。ファイルは変更しない。

このリポジトリは案件ごとに `job/<案件名>/MEMORY.md` (前提と決定) と
`job/<案件名>/STORAGE.md` (追記型アーカイブ) を持つ。知見をルート層へ昇格させる運用は取らず、
**必要になった時点でこのスキルが探索して読む**方式にしている。したがって探索の質がそのまま
アーカイブの価値になる。キーワード1回の grep で終わらせず、下の手順を最後まで通す。

## 引数

* **探索したいこと** — エラーメッセージ、技術名、やろうとしていること、など。
* 省略時は**現在の状況から自分で決める** (手順1)。

## 手順

### 1. 検索キーを決める

引数があればそれを起点にする。無ければ現在の状況から集める。

```sh
# 進行中の task (これが今の関心事)
find job -mindepth 4 -maxdepth 4 -path '*/task/progress/*' -not -name '.gitkeep'

# 案件の属性
for f in $(find job -mindepth 2 -maxdepth 2 -name MEMORY.md -not -path 'job/template/*'); do
  echo "--- $f"; sed -n '/^## 属性/,/^## 前提/p' "$f"
done
```

**`job/template/` は必ず除外する。** 複製元の注記に例として `Laravel` `認証` などの
技術名が書かれているため、除外しないと毎回テンプレートが先例としてヒットする。
`--exclude-dir` は macOS の grep ではコマンドラインで渡したディレクトリに効かないので、
下のように `find` でファイル一覧を作ってから grep する。

集めたものを4種類に分ける。

| 種類 | 例 |
| --- | --- |
| 技術 | Laravel, MySQL, Docker, GitHub Actions |
| ドメイン | 認証, 決済, 帳票, 予約 |
| 症状 | エラーメッセージ、失敗する操作 |
| 行為 | 移行, 権限設計, 性能改善 |

**表記ゆれと同義語まで広げる。** ここを怠ると引っかからない。
`Vue` なら `vue, vuejs, Vue.js`、`認証` なら `認証, auth, ログイン, OAuth, SAML`。
症状はエラーメッセージ全文ではなく、**固有名詞を除いた特徴的な部分**を使う。

### 2. 似た案件を絞る

現在の案件を除いた `job/*/MEMORY.md` の属性を突き合わせる。

```sh
find job -mindepth 2 -maxdepth 2 -name MEMORY.md \
  -not -path 'job/template/*' -not -path 'job/<現在の案件名>/*' \
  -exec grep -il -e '<キー1>' -e '<キー2>' {} +
```

一致したキーを案件ごとに数え、多い順に並べる。0件でも手順4は必ず実行する
(属性の書き漏れで引っかからないことがあるため)。

### 3. 候補を深く読む

**この順序で読む。** 上にあるものほど再利用価値が高い。

```sh
J="job/<候補の案件名>"
sed -n '/^## 踏んだ罠/,/^## 完了した task/p' "$J/STORAGE.md"  # 1. 罠
sed -n '/^## 完了した task/,/^## 畳んだ/p'   "$J/STORAGE.md"  # 2. 完了 task の結論
sed -n '/^## 決定/,/^## 進め方/p'            "$J/MEMORY.md"   # 3. 決定とその理由
sed -n '/^## 前提/,/^## 決定/p'              "$J/MEMORY.md"   # 4. 前提
```

罠と決定で当たりが出たら、**その根拠までたどる**。

```sh
grep -l '<キー>' "$J"/task/list/*.md | grep -v '/template\.md$'   # ## 結果 と ## 参照先
```

task の `## 参照先` に載っている `daily/.../<名前>.md` が過程の生ログなので、
**なぜそう決めたかが必要なときはそこまで読む**。結論だけで足りるなら task で止める。

### 4. 案件の外も横断する

属性で絞れなかったものを拾う保険。案件に紐づかない蓄積もここで拾う。

```sh
find job qa docs daily repos -type f -name '*.md' \
  -not -path '*/template/*' -not -name 'template.md' \
  -exec grep -il '<キー>' {} +
```

* **現在の案件のファイルは結果から除く** (自分の MEMORY.md が必ずヒットする)。
* `qa/resolved/` にリンクがある QA は**決着済みの判断**なので優先度が高い。
  `qa/unresolved/` のものは先例ではなく「同じ問題が未決着」として別に報告する。
* `daily/` は件数が多くなるため、当たったファイルの `## 分かったこと` だけを読む。

### 5. 評価する

**捏造しない。** 以下を守る。

* 一致根拠を必ず示す。「似ている」だけでは出さず、属性の何が一致したかを書く。
* **現在の状況との差分を必ず添える。** そのまま流用できない点を書かないと誤用される。
* 該当が無ければ「先例なし」と明言する。かすっただけのものを先例として出さない。
* 過去の決定は**当時の判断**である。現在も有効かは別問題として扱い、断定しない。

### 6. 報告する

下のフォーマットで出す。**引き出した知見が現在の task にとって重要な場合は、
その task の `## 参照先` への追記を提案する** (追記は確認を取ってから行う。このスキルは変更しない)。

## 出力フォーマット

```
検索キー: Laravel, 認証, SAML  (現在: job/acme-portal/ の progress タスク sso-setup)

先例 1: internal-tool (job/internal-tool/)
  一致: 技術スタック Laravel / ドメイン 認証
  罠     SAML のメタデータ更新後にキャッシュが残り旧証明書で検証が落ちる
         → 対処: config:clear ではなくキャッシュテーブルの直削除が必要 (2026-05-12)
  決定   IdP 側の属性名を変えず SP 側でマッピングした / IdP は他部署管轄で変更に2週間かかるため
  根拠   job/internal-tool/task/list/saml-mapping.md
         daily/2026-05/12/agents/claude-code/.../saml-cache.md
  差分   先例は社内 IdP (Azure AD)。今回は顧客提供の IdP なので属性名の交渉余地がある

先例 2: ...

関連 (先例ではない):
  未決着の同種 QA: 多要素認証の必須化範囲 (qa/list/mfa-scope.md)
  ドキュメント: docs/official/internal-tool/auth-spec.md

提案: 先例1の罠を job/acme-portal/task/list/sso-setup.md の ## 参照先 に追記しますか?
```

該当が無い場合は、探した範囲を示してから「先例なし」と報告する。

```
検索キー: Laravel, 認証, SAML
探索範囲: job/ 2案件の MEMORY.md/STORAGE.md、task 実体、qa/、docs/、daily/ 3ヶ月分
先例なし。認証を扱った過去案件は無い。
```
